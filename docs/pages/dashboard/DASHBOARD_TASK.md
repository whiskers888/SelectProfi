Твоя главная цель — чтобы Dashboard визуально и функционально соответствовал макетам.

Проверяй каждый экран по отдельности:

### Dashboard заказчика — `_2`

- Список заказов и вакансий.
- Карточки и детали.
- Shortlist кандидатов.
- Скрытие персональных данных.
- Все действия и переходы.

### Dashboard соискателя — `_3`
Проверь:
- Показатели и активность.
- Резюме.
- Отклики и их статусы.

## 4. ТРЕТИЙ ЭТАП — ФУНКЦИОНАЛЬНОСТЬ И BACKEND

Проверь цепочку:

`UI → API Client → Endpoint → Application → Database`

Убедись, что:
- Реальные данные приходят из backend.
- DTO соответствуют frontend-типам.
- Нет фиктивных production-данных.
- Нет неработающих кнопок.
- Ошибки API корректно обрабатываются.
- После мутаций данные обновляются.
- Доступ к данным ограничен ролью пользователя.
- Заказчик не получает закрытые персональные данные кандидатов.
- Миграции согласованы с моделями.

Не добавляй новые сущности, таблицы и API без реальной необходимости.
